# Git Practice — 콘솔 할 일 관리

Java 콘솔 기반 할 일 관리 프로그램을 만들며 Git과 GitHub의 개발 흐름을 연습하는 프로젝트입니다.

## 프로젝트 목적

작은 기능을 이슈 단위로 나누고, 브랜치 생성부터 Pull Request 검토와 병합까지 반복합니다.

주요 학습 대상은 다음과 같습니다.

- Git의 변경 확인, 스테이징, 커밋과 브랜치 관리
- GitHub Issues를 통한 작업 정의와 완료 조건 관리
- Pull Requests를 통한 변경 검토와 병합
- GitHub Projects를 통한 작업 상태 관리
- 충돌 해결과 변경 되돌리기

## 첫 버전의 범위

첫 버전은 프로그램 실행 중 메모리에 할 일을 보관하는 방식으로 구현합니다.

구현할 기능은 다음과 같습니다.

- 콘솔 메뉴와 실행 흐름
- 할 일 추가
- 할 일 목록 조회
- 할 일 제목 수정
- 할 일 상태 변경
- 할 일 삭제
- 잘못된 입력에 대한 안내

할 일은 번호, 제목, 상태를 가집니다. 상태는 `할 일`, `진행 중`, `완료`로 구분합니다.

첫 버전에서는 프로그램을 종료하면 데이터가 사라집니다. 파일 저장, 우선순위, 검색은 이후 확장 대상으로 둡니다.

## 실행 방법

이 프로젝트는 Java와 Maven을 사용합니다.

Java 버전과 구체적인 실행 명령은 초기 프로젝트 설정을 확인한 뒤 이 문서에 추가합니다.

## 작업 방식

각 기능은 GitHub Issue에 완료 조건을 작성한 뒤 구현합니다.

1. 작업할 Issue를 선택합니다.
2. 최신 `main`에서 작업 브랜치를 만듭니다.
3. 기능을 구현하고 완료 조건을 확인합니다.
4. 변경 사항을 커밋하고 GitHub에 올립니다.
5. Pull Request를 만들고 변경 내용을 검토합니다.
6. 병합 후 해당 Issue를 닫고 작업 브랜치를 정리합니다.

하나의 Issue는 가능한 한 사용자가 확인할 수 있는 동작 하나를 완성하는 크기로 정합니다. 기능 구현에 필요한 클래스 작성과 메뉴 연결은 같은 Issue에 포함합니다.

## 개발 순서

1. 콘솔 메뉴와 실행 흐름 구현
2. 할 일 추가 구현
3. 할 일 목록 조회 구현
4. 할 일 제목 수정 구현
5. 할 일 상태 변경 구현
6. 할 일 삭제 구현

세부 작업과 진행 상태는 GitHub Issues와 Projects에서 관리합니다.
